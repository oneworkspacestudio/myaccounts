# Preview 20261030.1: OneAccount MFA

Enrol One Authenticator from account MFA settings. A server-held five-minute
pending seed becomes active only after a valid code. Save ten recovery codes.
The independent phone vault works offline without a OneAccount session.

Server seeds use account-bound AES-GCM and a separate machine-DPAPI protected key.
Recovery codes use account-bound digests and atomic consumption. Persistent
factor limits span challenges and IPs. TOTP replay, challenge completion and
credential transitions use atomic database operations. Ordinary user APIs omit
seeds and recovery digests. Setup, regeneration and removal require password verification within five
minutes plus current or recent MFA evidence. The settings UI asks for the password
again for each action. After a successful MFA sign-in,
factor evidence lasts five minutes, allowing recovery with the last remaining code.
Raw OTPs and recovery codes remain single-use.

Activation revokes prior tokens. MFA session proof gates JWT creation, refresh,
protected APIs and user-token introspection. Noninteractive user grants fail
closed for TOTP users. Removal revokes every user session/token atomically.
Managed deployment requires Workspace109 with oneaccount-mfa-v1; an older
manager must update first. Workspace validates old SSO sessions and proxied
streams against provider proof. Install the paired suite update for that protection.

Verified with fresh synthetic NTFS installations: adversarial native HTTP/OIDC,
PKCE and signed token flow, replay and concurrent recovery, cross-flow rate limits,
prior session/token/refresh denial, encrypted backup/restore and actual browser
settings provisioning of an independent offline PWA. No owner data used as fixture.
Physical Android/iPhone, reboot and clean-host tests remain open. TOTP is not
phishing resistant. Browser storage is not hardware-backed. Lost-all-factor
maintenance recovery remains supervised; no unauthenticated email bypass exists.
Security notifications are persisted in account settings; email/push is not promised.

Evaluation preview, not a production security certification. See the paired
[One Authenticator security model](https://github.com/oneworkspacestudio/one-authenticator/blob/main/docs/SECURITY.md).
