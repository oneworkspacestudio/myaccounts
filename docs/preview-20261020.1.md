# MyAccounts preview-20261020.1 candidate

This update binds each authorization code to the exact `redirect_uri` used in
its authorization request. The token endpoint rejects an omitted, changed or
different registered callback, before consuming the legitimate code. Both form
and JSON token input are covered. Internal CasWAF callbacks supply the same
original URI. Invalid-code/verifier errors do not echo the submitted secret.

The database change adds one private text column. Existing accounts, signing
keys, browser sessions and issued access/refresh token records are retained.
Codes issued by an older server without the binding must restart authorization;
an existing MyAccounts session can complete that restart without a new password.
Relying parties must send their original callback URI on token exchange.

## Actual development-binary verification

- Native regression tests, focused whole-object binding tests and static analysis
  passed on Windows. Browser assets type-checked and built before the executable.
- A real synthetic browser completed S256 authorization; a separate Node HTTP
  client redeemed the code without a client secret or copied browser cookies.
  Signature/JWKS, issuer, audience and nonce were verified.
- Wrong verifier, changed URI, another registered URI, omitted URI, replay and
  concurrent exchange were tested against the actual provider. Exactly one of
  two concurrent exchanges succeeded. Failed validation left the valid code usable.
- The released predecessor's existing synthetic SQLite database upgraded and
  restarted. Its unbound pending code was rejected; its previously issued access
  token and subject remained valid, and browser SSO remained usable.
- Integrated Chat retained immutable identities, a message, attachment link and
  the actual browser download filename and exact document bytes.

The companion harness is in the Chat repository under
`scripts/workspace/native-oidc-acceptance.cjs`. It uses only protected disposable
fixtures. No owner account or live database was used.

## Build and limits

Use `scripts/build.ps1`. `-WebBuild` accepts a named NTFS copy of the same browser
sources when the source checkout is on exFAT; inputs are verified before building.
`-YarnPath` can select the pinned Yarn1.22.22 CLI without a global installation.
Locked download URLs now use the official npm registry transport; package versions
and integrity hashes are unchanged. No TLS verification is disabled.

This is a candidate, not production v0.1.0 approval or native Chat mobile delivery.
Independent clean-host, service/reboot, cross-machine restore, full provider/app
regression, dependency and licensing gates remain as recorded in the acceptance
ledger. No GitHub Actions are used. Final artifact/download checks are recorded
separately from these development checks; no draft asset is proof of publication.
